# zClaw child role prompts

These files are reusable prompt text for zClaw children started through zClaw `sessions_spawn`. The expected working style is objective-first, concise, direct, and evidence-led. For private work, stay blunt and efficient. For clients, partners, public channels, or other external audiences, use neutral, professional wording. Protect z's private data and do not impersonate z.

These prompts guide behavior; they do not grant, restrict, or configure runtime permissions. They do not load automatically as zClaw agent definitions.

For every spawn, the parent must select model, thinking, timeout, sandbox, and other available per-run options through `sessions_spawn`. Tool access is governed by the active zClaw runtime policy and exposed tool set, not by these prompts. Verify routes and tools before relying on them. Do not infer availability from another environment. Concurrency limits are runtime or orchestrator policy; text here does not set a global `maxConcurrent` value.

Include the relevant role prompt in a bounded task with its objective, allowed scope, constraints, deliverable, and acceptance criteria. Keep private data within authorized sources and include only what the task needs. No child may commit, push, sync branches, contact people, or mutate a live service unless z explicitly authorized that action. zClaw edits and verifies files; z owns commits, pushes, branch sync, remotes, and repository history by default.
